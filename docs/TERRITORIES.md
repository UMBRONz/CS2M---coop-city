# Режим «Территории» — у каждого мэра своя земля и своя казна

Кооп для Cities: Skylines II поверх CS2M. Одна карта на всех, карта поделена на клетки (23×23),
каждый игрок развивает свою территорию на своём бюджете. Дальше — торговля между мэрами
(электричество, вода, грузы), кредиты, общие объекты на границе.

## Архитектура

```
CS2M.Territories.Core   чистые правила, без игры и Unity (netstandard2.0) + юнит-тесты
  TerritoryState        кто владеет клеткой, баланс каждого игрока; клетка <-> мировые координаты
  TerritoryAuthority    решения хоста: старт-зоны, покупка клетки, проверка стройки, переводы, месячный расчёт
  ChatCommandParser     /land /claim /money /give
CS2M.BaseGame/Territories
  TerritoryCommands     сетевые команды (запросы клиента, снимок, события, отказ)
  TerritorySession      хост: держит Authority; клиент: держит реплику, шлёт запросы
  TerritoryHandlers     обработчики команд (CS2M находит их рефлексией)
  TerritoryBuildGuardSystem  ECS-система: превью инструмента вне своей земли -> Error (красное, не ставится)
CS2M/Territories/TerritoriesBridge  связывает события сети CS2M с сессией
```

Модель: **хост решает всё про землю и деньги**, клиенты только просят. Хост рассылает
события-результаты (новый владелец, новый баланс), а не дельты, поэтому повтор или опоздание
события безопасны. Новый игрок получает полный снимок и свой id.

Правки в самом CS2M (нужны любому режиму, кандидаты в апстрим):
- `RemotePlayer.PlayerId = peer.Id`, хост = −1 (раньше у всех был 0);
- хост сам проставляет `SenderId` из пира — клиенту не доверяем;
- `Command.SendToPlayer(id, cmd)`; `Command.CurrentRole` теперь выставляется.

## Правила по умолчанию (`TerritoryConfig`)

| | |
|---|---|
| Стартовая зона | 3×3 клетки; двое игроков стартуют слева и справа от центра, между ними нейтральная земля |
| Стартовые деньги | 500 000 у каждого |
| Покупка клетки | только соседней со своей; 100 000, каждая следующая +10 % |
| Стройка | только на своих клетках, и только если хватает своих денег |
| Месячный расчёт | налоги минус содержание всего, что стоит на клетке, идут владельцу клетки |

## Что проверено, а что нет

Проверено: 26 юнит-тестов ядра (`dotnet test CS2M.Territories.Tests`); сетевой слой
(команды, сессия, обработчики) компилируется вместе с CS2M.API.

**Не проверено в игре** (игра не была установлена): `TerritoryBuildGuardSystem` и правки в CS2M
не собирались против `Game.dll`. Первым делом в игре проверить:
1. инструмент отказывается ставить превью, если на `Temp`-сущности есть `Error`;
2. `ValidationSystem` не снимает наш `Error` в том же кадре (порядок систем в `ToolUpdate`);
3. поле `Temp.m_Cost` существует и это цена превью.

## Дорожная карта

1. **Собрать и запустить** с официальным тулчейном (Options → Modding в игре ставит его и
   задаёт `CSII_TOOLPATH`). Проверить три пункта выше.
2. **Синхронизация стройки** — главная недостающая часть CS2M: при применении инструмента
   рассылать действие (дорога, зона, здание, снос, район), другие клиенты повторяют его.
   Хост при этом списывает стоимость с казны строителя (`CheckBuild`).
3. **Деньги игры = казна игрока**: показывать в UI свой баланс вместо общего городского.
4. **Месячный расчёт по клеткам** (налоги/содержание по позиции зданий) -> `SettleMonthOnHost`.
5. **Сохранение**: снимок территорий в файл рядом с сейвом, восстановление при загрузке хостом.
6. **UI**: подсветка своих/чужих клеток на карте, покупка клетки кликом вместо `/claim X Y`.
7. **Пересинхронизация** от хоста по кнопке (симуляция жителей на разных ПК расходится).
8. Экономика между мэрами: продажа электричества/воды через границу, кредиты, грузы.

## Команды в чате (временно, до UI)

`/land` — мои клетки и что можно купить · `/claim X Y` — купить клетку ·
`/money` — казна всех мэров · `/give ИГРОК СУММА` — перевести деньги
